Each check is one thing the test watched boat.dev do on its real host.

  1. versionpassedIt names the kernel's records version, and prints its schema unchanged.
  2. startpassedIt answered a run id, and the agent's status note appeared on a throwaway ticket.
  3. wakepassedIt reached the same run again: that note was edited, never a second one.
  4. stoppassedIt ended the run: a wake after it was refused, and nothing the run started still runs.
  5. tokenpassedNo credential appeared in its output, command lines or environment, and it refused a token field.

Cloudroom and your own computer or VPS passed the same five checks on 2026-11-20.

Hosts that need an API key

Some hosts can be driven only through an API that takes your key. Their drivers keep one more rule of the contract:

  • The key lives only on your computer: in your system keychain, or in an environment variable you set.
  • OpenWiz never stores it. To revoke OpenWiz's use of it, clear every place you put it, both the keychain entry and the environment variable, then restart anything that inherited the variable.
  • hostkey.py, one small helper in the kernel's driver kit, is the only thing that reads it. It sends the key only over HTTPS to that host's own registered address.
  • The driver never sees it, and the kit checks that.
  • Every driver still has to pass the same five checks, so a host that can't wake or stop a run gets no driver.

Write your own driver

A driver is one small program, in any language, that answers four commands, plus its schema. Pass the same five-check test on your real host and it can join. OpenWiz never touches a login.

Platforms: the test, the template, and the boat.dev and own-computer drivers run on Linux and macOS, with a supported version of Python installed (see the driver requirements).
