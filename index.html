    The video
    The spec

    Problem Statement

    You want a simple place to write down what you need to do and tick it off. Nothing here does that yet: the app is a placeholder page.

    Solution

    A to-do app in the browser with one list for now. You type a task and add it; it appears in the list. You tick a task to mark it complete: it stays in the list, greyed out, and you can untick it. Your tasks are kept after a reload. The app is a static page on GitHub Pages, with no account and no server: tasks live in your browser.

    Changelog headline

    A to-do app with one list: add a task, mark it complete (it stays, greyed out), and your tasks are kept after a reload.

    User Stories

    1. As a user, I want to type a task and add it, so that it is in my list.
    2. As a user, I want an empty task to be refused, so that my list holds only real tasks.
    3. As a user, I want to mark a task complete, so that I can see what I have done.
    4. As a user, I want completed tasks to stay in the list, greyed out, so that I can still see them.
    5. As a user, I want to untick a completed task, so that a mistaken tick is easy to undo.
    6. As a user, I want my tasks kept after a reload, so that closing the tab loses nothing.
    7. As a user, I want the app to work on my phone and with the keyboard, so that I can use it anywhere.

    Implementation Decisions

    • One list for now: no named lists, no list switching. Tasks keep the order they were added in.
    • The task list, first (contract-first ticket): app/todos.js is a dependency-free ES module of pure functions that every other ticket builds on. A task is { id, text, done }. addTask(tasks, text) returns a new array with the trimmed text added at the end, or the same array for blank text; toggleTask(tasks, id) flips done; loadTasks(storage) and saveTasks(storage, tasks) read and write one localStorage key, todo-demo.tasks.v1, as JSON, and a missing or unreadable value loads as an empty list. docs/markup.md fixes the list's markup and class names (the form, the list, one item, its checkbox, and the done state) so the view and the styles agree.
    • The view: app/view.js turns tasks into the list's markup as docs/markup.md says, escaping task text.
    • The page: app/index.html and app/main.js wire it up: load at start, add on submit, toggle on the checkbox, save after each change, render.
    • The look: app/style.css: a calm single column that fits a phone; a completed task greyed out with its text struck through; visible keyboard focus.
    • No dependencies, no build step. GitHub Pages serves app/ after every merge to main.

    Testing Decisions

    • npm test (node --test) proves the task list and the view at their module seams: app/todos.js and app/view.js, with an in-memory stand-in for localStorage.
    • The page itself has no browser test (no dependencies); it is proven by the live check.

    Out of Scope

    Several or named lists, editing or deleting a task, due dates, sync between devices, accounts.

    Further Notes
