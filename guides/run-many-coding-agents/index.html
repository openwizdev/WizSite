How to run many coding agents at once

An agent factory is a system that turns a plan you approve into merged code: each small ticket goes to its own AI coding agent, and another agent reviews the work before it merges. A fleet of coding agents is the group of builder and reviewer agents, such as Claude Code or Codex, that an agent factory runs at the same time, each on its own branch.

Why one agent at a time stalls

One coding agent in one terminal writes code quickly, but the work around it stays manual. You write each prompt, wait, read every change and decide what comes next. The pace is set by how fast one person can review and coordinate, not by how fast the agent types.

Opening more terminals does not fix this on its own. Several agents on one repository need separate, clear tasks, their own branches, a check on every result and a shared record of what is done. Without those, the time the agents save goes into sorting out overlaps and reading diffs.

What an agent factory does

An agent factory replaces that hand coordination with a fixed process. You make the decisions; the agents do the rest.

  • Spec: an agent asks you a few questions about your idea, then writes it up as a spec for you to confirm.
  • Tickets: the spec becomes small tickets, a plan you approve as a whole.
  • Builders: each ticket gets its own builder agent, which writes the code on its own branch and opens a pull request.
  • Reviewers: a reviewer agent from a different model family checks each pull request on its own.
  • Merge: approved work with passing checks merges by your project’s rules.
  • Records on GitHub: specs, tickets and each agent’s status live in your repository’s issues, so you, your team and your agents read the same record.

Running a fleet with OpenWiz, step by step

These steps are for OpenWiz 0.01 (version 0.1.0), the current release. You need an Apple-silicon Mac or x86_64 Linux, a GitHub repository and a coding agent you already use.

  1. Install OpenWiz. Paste Install OpenWiz from github.com/openwizdev/OpenWiz into Claude Code, Codex or another coding agent. It shows every change first and waits for your yes.
  2. Choose where your agents run. The install asks: this computer, with the Claude Code or Codex you’re signed in to; boat.dev; or CloudRoom. CloudRoom is optional, and the install never needs it.
  3. Plan the work. Pick a repository and say what you want. Your agent grills you with a few questions, writes the spec for you to confirm and splits it into tickets on GitHub. Nothing starts until you approve the plan.
  4. Start the builders. With CloudRoom, the automatic fleet runs there: builders and reviewers start and wake on their own. Without CloudRoom, in OpenWiz 0.01 you start each ticket’s builder by hand on this computer or on boat.dev.
  5. Review and merge. In the CloudRoom fleet, a reviewer from a different model family reviews each pull request, and approved, green work merges by your project’s rules. Without CloudRoom, you review and merge each pull request yourself.
  6. Watch it ship. Follow the specs, tickets and pull requests on GitHub, or sign in to the app, which only reads your GitHub.

Where the agents run

A driver connects OpenWiz to the machine that runs your agents. OpenWiz 0.01 ships drivers for your own computer or VPS, CloudRoom and boat.dev, and each answers the same four commands: version, start, wake and stop. Your agents keep using their own signed-in tools, and OpenWiz never touches a login. See the driver list for which drivers passed the test kit.

What it costs

You pay only for the models and machines you use: your Claude Code or Codex plan, and any host you pick. boat.dev bills per second while a sandbox runs, and CloudRoom’s charges are its own, on your plan with it.
